# 04 · 派发与接收规则

## 1. 派单字段（精简六项）

| 字段 | 填写要求（本项目固定值） |
|---|---|
| 目标与输入 | 事项 ID + 步骤号；输入 = `01` §4 的文件清单 + 权威规格 `eve战局沙盒推演软件交接.md` |
| 写入范围 | 事项卡「允许写入范围」；共享文件单一写入者：`src/ui/main.ts`、`src/ui/protocol.ts`、`src/ui/viewModel.ts` 由主代理持有，实施者需改动时先交回 |
| 关键约束与授权 | 见 `00` 权限表；C1–C4 与 §3.2 已知坑不可回退；`SideId = number` 不可回退 |
| 产物与验证 | 事项卡 AC 表；局部命令见 `00` 能力表 |
| 停止 / 异常交回 | 打包发布、改冻结规格、改 `docs/第4章-PYFA集成协议-冻结稿.md` 时停止；连续同类失败 3 次（无新假设）停止本步改为诊断 |
| 主代理接收动作 | 亲自运行 `00` 能力表里的决定性命令；核对真实 DOM / 命令日志 / 截图，不采信实施摘要 |

## 2. 持续执行

在权限表范围内，源码读写、构建、断言、无头浏览器验收、本机 dev-host 启动可持续执行，不必逐轮询问。到达停止点交回；可继续的已授权步骤照常推进。

## 3. 变更交接（合同变更）

新增门禁或授权变化时，主代理建立**具名增补**（ID + 标题）或新版本，记录：原版本、变更原因与用户决策来源、替代条款、生效点、受影响事项/AC/证据。读取顺序须指明有效合同，避免旧限制继续生效。

向实际实施负责人同步变更，需先核对是否有对应的消息发送授权；无授权时保留"未同步"状态并交付可转交材料，不宣称负责人已采用新规则。

## 4. 长时运行控制

- **进度通道**：`03-台账与恢复状态.md`（每次状态迁移更新）。
- **阶段检查时点**：每个事项的最后一个步骤完成即为一个检查点；不设固定时长定额。
- **静默期核验**：以文件实际改动 + 命令输出为准；进程存在只表示活性，不代表进展。
- **重试**：可重试错误（dev-host 未就绪、浏览器 CDP 端口占用）退避 3 次，每次 2 s；同类失败无新假设到第 3 次停止本步并交回诊断。
- **资源清理**：dev-host 用毕必须 `Stop-Process`；`tools/browser-check.ts` 与 `v07-flow-check.ts` 自带临时 profile 清理（`finally` 中 `rmSync`）。
- **越界处理**：出现越界写入、虚报通过或破坏门禁的情况，拒绝返回并停止其写入资格。

## 5. 实施返回

| 字段 | 内容 |
|---|---|
| 身份 | attempt ID、事项/步骤、有效合同版本 |
| 状态 | `checkpoint_ready` / `blocked` / `failed` / `budget_exhausted` |
| 变更 | 真实文件列表 + 改动摘要 |
| 结果 | 落实的 AC 编号、实际执行命令与退出码、原始输出路径 |
| CI | 三事项均为"不适用"；本地检查结果列出命令与输出 |
| 失败 | 失败签名、假设、修改、结果、已用重试次数 |
| 未完成 | 未验证项、风险、外部依赖、建议下一动作 |
| 写入 | 停止写入确认；dev-host 等受控进程已停止 |

## 6. 主代理接收

1. 对照 `01` §4 的文件清单核对范围与越界。
2. 亲自运行决定性命令：`node tools/build-ui.ts`、`node tools/engine-test.ts`、`node tools/sde-test.ts`、`node tools/theater-test.ts`、`node tools/v07-flow-check.ts`。
3. 人工类 AC（T1/T2/T3）核验截图与操作记录，逐条对照 AC 表；缺失即 `needs_evidence`。
4. 人工验收与自动化分别记录；本地通过只计入本地验证（本项目无远程）。
5. 记录 `accepted_checkpoint` / `rejected` / `needs_evidence`、证据路径、剩余 AC 与下一动作，更新 `03`。

## 7. 中断与恢复

1. 先确认旧实例与其受控写入任务停止（`Stop-Process` 清理 node/dev-host）。
2. 核对 `01` §4 文件清单与 `03` 的基线数字是否仍成立。
3. 重派使用新 attempt ID，绑定接受的输入身份（文件清单 + 基线数字）。
4. 先交一个代表性可核验步骤（建议 T1 步骤 2：跑通一次完整生成推演），确认环境可用后再恢复较大范围。
5. 未核验的半成品标记 `unverified`，保存失败原因与下一动作。

- `交接1/evidence/T1/` — 沙盘交互截图与操作记录（T1 建立）
- `交接1/evidence/T2/` — 表单交互截图（T2 建立）
- `交接1/evidence/T3/` — 装备交互截图与 DOM 快照（T3 建立）
- `交接1/evidence/T4/` — 多势力运行记录（T4 建立）
- 命令输出：直接粘贴进 `03` 对应检查点条目，或存为 `交接1/evidence/<attempt>-<命令>.log`
