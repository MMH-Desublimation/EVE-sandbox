### 2026-10-09 · 沙盘可读性 · 无人机闪烁 · 卡死 · 左侧/右键选中（用户诉求一批）

用户报障六项，逐条修复如下（全部仅改 UI 层 + 一处引擎环绕数学，未改协议）：

**① 沙盘只显示舰船图标，不写舰船名字**（`view/map.ts`）
- 名字绘制改由开关 `#showUnitNames` 控制，**默认关**；计数 `#labelsDrawn` 供验收卡住"别画回来"。
- 验收 §5b：`labelsDrawn=0` 且 `unitNames=false`。

**② 射程环 / 锁定环只在"点选单个单位"时显示**（`view/map.ts`）
- `#drawSelectionRings` 守卫由 `#selected.size === 0` 改为 `!== 1` → 框选（多选）**一个环都不画**。
- 新增渲染自检 `#ringsDrawn`（在 `#drawRing` 真正落笔处累加）+ `map.renderStats()`。
- 验收 §5b：单选 `ringsDrawn=2`，框选 4 个 `ringsDrawn=0`。

**③ 无人机图标"频繁闪烁、聚散移动"**（`view/map.ts`，**本轮主根因**）
- **根因**：组的 id 是**母舰内局部编号**（`d:<typeId>:<序号>`），并非全局唯一 —— 12 艘船各带同型无人机时组 id 全是 `d:2478:0`。`#prevGroups` 插值快照只拿组 id 当键 → 各船快照互相覆盖，渲染时把 A 船无人机的上一拍位置配到 B 船无人机上，图标在几艘船之间乱跳。
- **改法**：新增 `#groupKey(hostId, groupId) = "<母舰id>#<组id>"`，快照表、`#drawGroups`、`probeGroupPos`、`groupIds()` 全部改用该唯一键；`probeGroupPos` 兼容裸组 id。
- **验证前/后**（`v07-flow-check` §3c，采样组自身渲染位置 1.6 s / 1×）：
  `backwardRatio 0.948 → 0`，`medianM 776 → 26.4`（m/帧），`frozenRatio 0 → 0`，`jumpP95Ratio 61.8 → 1.11`。
- 附带修 `core/sim.ts` 环绕数学：原沿切线**直走**再被拉回，半径每 tick 涨一点 → 径向"呼吸"；
  改为**圆弧旋转**（`ORBIT_MAX_TURN_RAD = 0.4` 封顶转角），半径恒定。

**④ 大规模战斗 / 拖时间轴"程序完全卡死"**（`worker/sim.worker.ts` + `view/panels.ts`）
- **根因**：worker 用 `void handle(data)` **并发**处理消息，而时间轴 `input` 每个像素都发 `seek` →
  几十个关键帧重算同时跑在同一个 Runner 上，互相踩状态、再也回不来。
- **改法**：worker 内建**串行队列** `queue` + `pumping` 单泵消费；连续 `seek` **合并**为最后一个；
  `statsResponse` 走快路径立即回（否则队列排到它会死锁）。UI 侧 `input` 节流 120 ms，`change` 才发最终 seek。
- 验收：`v07-flow-check` 全程拖时间轴 / 重算不再卡死（§6 终止、§7 重进沙盘均通过）；`perf-test 250` 双 PASS，UI 投影 0.33 ms/帧（2% 帧预算）。

### 2026-10-08 · 沙盘运动平滑（用户诉求第 1 项）

- **现象**：UI 不卡，但舰船位置"分段跳变、不连续"。
- **根因**：`view/map.ts` 原用**单点速度外推**（位置 = 帧坐标 + 本拍速度 × 帧后游戏时间）。
  引擎每个 tick 内是加速度收敛运动（`geometry.stepMovement`），船在加速 / 转向时
  外推直线与下一 tick 真值对不上，每到一个 tick 边界就被"拽"一下；帧到达抖动
  （20Hz 发帧 vs 60Hz 采样）还会让 α 提前撞顶、出现半拍冻结。
- **改法**（仅 `view/map.ts` + 注释，未动引擎与协议）：
  1. 相邻两个 tick 快照之间做**三次 Hermite 插值**（两端位置 + 两端速度），
     跨 tick 边界不再有折角；
  2. α 用**实测拍长的指数滑动平均**，倍速切换时由 `setClock` 重置为 `1000/倍速`；
  3. α 允许到 1.5，超出部分沿本拍速度做短距线性延拓，消除"等下一拍"的冻结感；
  4. 舰载机 / 无人机各自独立快照插值；
  5. 暂停 / 重算 / 结束不插值，直接画当前真值。
- **验证**：
  - `build-ui` 44 模块；`engine-test` 24/24；`sde-test` 35/35；`theater-test` 96/96。
  - `v07-flow-check` 连续 3 次全绿。流畅度块：`frozenRatio` 三档基本为 **0**，
    `backwardRatio ≤ 2.1%`，`jumpP95Ratio ≈ 1.07~1.11`（4× 个别次 1.65，见下），
    `medianM` 与实际倍速误差 ≤ 1.5%。
- **顺带修了度量本身**：`window.__ui.smoothness` 只有 `jumpRatio = max/med`，单帧
  GC 抖动就能把它顶到 6.5，验收会随机红。新增 `jumpP95Ratio`、`bigStepRatio`，
  验收改判这两个（`max` 保留但只粗筛 ≤10）。
- **代价**：画面比引擎真值晚约一个 tick（4× 下 250ms）。暂停 / 重算时为零延迟。
- **已知纹波**：4× 时一个 tick 只摊到约 5 个发帧，而 tick 到达与渲染帧格不对齐，
  段长在 4~6 帧之间跳 → 步长有 ≈1.5× 的量化纹波（`jumpP95Ratio` 偶尔 1.65）。
  观感上是一点速度涟漪，不是跳变；若要抹平需降低 `FRAME_MS` 或改用合成均匀时间轴。
