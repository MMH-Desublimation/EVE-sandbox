# EVE 战局沙盒推演

一个 **Windows 桌面程序（独立窗口、完全离线）**：在图形沙盘上布置红蓝双方舰队，
程序按《EVE Online》机制**确定性地**推演接战全过程，输出战损与战报。

- **定位**：策略工具（预演可能性），不是 EVE 游戏本体的简化版。
- **数值权威**：一切数值以 **PYFA** 为准（技能全 V 级）。
- **完全离线**：不联网、无自动更新检查。

> 交接与决策文档：`eve战局沙盒推演软件交接.md`
> 第 4 章（PYFA 集成协议）冻结稿：`docs/第4章-PYFA集成协议-冻结稿.md`
> SPIKE 报告：`spike/SPIKE-001-报告.md`

## V0.8 变更（本版）

| # | 变更 | 说明 |
|---|---|---|
| 1 | **增援势力归属修复** | 弹窗原先写死 `1=红方/2=蓝方`，而引擎是 **0=蓝方/1=红方** → 选「蓝方」会落到不存在的 sideId=2（显示成「3号势力」、找不到星门、拿不到配色而看不见）。现改为**数据驱动**（真实 sideId + `sideName`），默认跟随选中单位的势力 |
| 2 | **增援永远新开舰队** | 原先 `fleetId/wingId/squadId = 0`，与该势力原有编队的 key 相同 → 被合并进原小队行、看起来"没显示"。现取「该势力最大舰队号 + 1」，整批进一个**新舰队**，左侧树标注「增援舰队 N」 |
| 3 | **单次增援上限 256** | 引擎两条路径都截断；弹窗输入 `max=256` |
| 4 | **星门落点兜底** | 优先本方星门 → 中立星门 → 任意星门；都没有时退化为本方舰队形心（不再是 (0,0) 空白处） |
| 5 | **增援后不再拉远镜头** | 上次的自动「适应全体」在星门（战场外 140 km）场景下把镜头拉到极远；现改为**自动选中新部队** |
| 6 | **批量指令卡死修复（核心）** | ① 每条命令都从 t=0 重建整场 → 新增 `Runner.addCommands`，worker 把连续的 command 消息**合并为一次重算**；② 属性缓存按「单位」存键 → 改为**按配装签名**（同配装共享）；③ 预热的组合枚举按单位做 2^n → 改为**只对「关」类指令**做闭包（批量「开启装备」不再组合爆炸）。实测 200 单位 + 12 条批量开关：**预热 14 ms** |
| 7 | **重建失败不再破坏战场** | `#rebuild` 改为「全部成功才替换 `#battle`」——旧实现在推进中途抛错会把战场留在 t=0/半途，用户看到「点暂停/播放后整个沙盘被重置」 |
| 8 | **错误不再让界面卡死** | worker 命令泵逐条兜底：失败即报错 + 复位 busy + 推帧，不再永久停在「重算中」；重算失败还会**回滚命令表**（否则坏命令会让之后每次重算都失败） |
| 9 | **交火模式默认「自动攻击」** | 交火模式固定为四种（集中火力/自由开火/自动攻击/集火舰载机）、**永远是其中之一**（右侧会高亮当前模式）；默认「自动攻击」，武器因此默认能打起来 |
| 10 | **走位与交火模式解耦** | 交火模式只决定「打谁」，**不再**让舰船自动朝敌人移动 —— 走位只由机动指令决定（同时满足"默认能开火"与"不要默认朝敌移动"） |
| 11 | **图标分离加每帧配对预算** | 分离网格在单位多/视野拉动时会退化成一格 → O(n²) 每帧几十万次 hypot，表现为点击即卡死。现每帧上限 2 万对，超预算本帧不推挤（实测 800 重合单位 5 帧 22 ms） |
| 12 | **「跃迁至」+ 真实跃迁** | 右键目标（舰船/星门/建筑）→「跃迁至…」→ 落地距离 0/10/20/30/50/70/100 km。**起跳时间（对齐）+ 按跃迁速度旅行**，不再是"平速跑过实际 AU 距离"；**星门增援过门后也改为跃迁** |
| 13 | **跃迁许可（与旗舰跳同源）** | 距离 > 150 km；拦截力场 → 直接禁止；扰频(-2)/扰断(-1) 扣**跃迁稳定系数**，**≥1 才允许**。系数来自 PYFA：夜神级 = 1+5×技能5 = **26**（被扰频+扰断后仍可跃迁） |

## 战区机制（§9.1 补齐）

### 地物与玩家建筑

两者是**不同**的东西，别混：

| | 地物（Celestial） | 玩家建筑 |
|---|---|---|
| 例子 | 星门、空间站 | 星城（Keepstar）、铁壁（Fortizar） |
| 建模 | `BattleState.celestials`（坐标锚点） | **就是单位**（`state.units` 里的 `role: "structure"`） |
| 能力 | 不可装配、不可开火、不可摧毁（§9.2） | 可装配、可开火、可被摧毁（§9.1） |
| 数据 | 场景声明 | PYFA 完整叠加链 |

★ 关键实现坑：PYFA 的 `Ship(item)` **拒绝建筑**（`ValueError: ... is not under Ship category`）。
建筑必须走 `eos.saveddata.citadel.Citadel`（它是 `Ship` 的子类，用法一致）。
实测铁壁：护盾 675 万 / 装甲 540 万 / 结构 2160 万，最大速度 0。

### 旗舰跳

区分**能力**与**允许**（用户要的"判定允许进行旗舰跳情况下"就是后者）：

- **具备**：船有跳跃引擎（SDE `jumpDriveRange > 0`）。★ 该字段单位是**光年**（启示级 3.5，
  泰坦 3.0，跳跃货舰 5.0），不是米——当米用会把跳跃距离算成 3.5 m。
- **允许**：有引擎 + 存活/未撤离 + 冷却已过 + **未被反跳**（warp scramble / 拦截泡）+ 场景允许。

跳跃是**瞬移 + 冷却（含疲劳累加）**，与"普通跃迁"（对齐 → 飞行 → 离场）完全不同。

### 增援

| 方式 | 行为 |
|---|---|
| **星门派遣**（`mode: "gate"`） | 先在己方星门落地 → **过门延迟**（默认 6 s，期间不可被锁定）→ 自动执行机动 |
| **旗舰跳增援**（`mode: "jump"`） | 直接瞬到右键坐标（密集圆阵），并计入旗舰跳冷却 |
| **旗舰跳撤场**（`jumpOut`） | 仅在**允许旗舰跳**时生效；被反跳则拒绝，原因写入 commandLog |

增援编成（`BattleConfig.reserves`）的属性在**开跑前一次性预热**，因此运行中的增援指令
仍是纯同步的 —— 引擎保持确定性、可快照、可重放（实测：同命令跑两次指纹一致）。

### 入场编队：密集圆形阵列

任何入场（推演开始 / 跃迁落地 / 旗舰跳落地 / 星门增援）都落成**密集圆阵**，
不是方阵。用 Vogel 向日葵模型（`r = R·√(i/n)`，`θ = i·黄金角`），
`R = 0.52·spacing·√n`，纯函数因此天然确定（`src/core/formation.ts`）。

### 图标碰撞体积

沙盘上图标可以**短暂重叠**，持续约 1.5 s 后自动移动到最近的非重叠位置。

★ 这是**纯显示层**偏移（`src/ui/view/separation.ts`），**绝不修改引擎坐标** ——
引擎位置仍是唯一真源，显示位置 = 引擎位置 + 分离偏移；拾取判定也用显示位置。

★ **只在默认初始视距下生效**（V0.7）：分离半径按 `像素半径 / scale` 换算，
视野拉远时会被放大到几十 km，把图标推到离真实坐标很远的地方（看起来像乱动）。
现在只要 `scale` 低于取景时记录的初始视距，就**停止避让并把偏移归零**。

### 舰船标识（用户提供线稿）

`src/ui/assets/ships/<吨位>.png`（16 个，纯白线稿）。

吨位归类建立在 **SDE 的 Category/Group** 上，**不对船名做正则猜测** ——
因此用户的规则自然成立：多米尼克斯级 / 多米尼克斯级海军型 / 罪恶级 / 克洛诺斯级
同属 `Battleship`/`Black Ops`/`Marauder` → 都用 `battleship.png`。

染色：默认按**本沙盒的势力**（红/蓝）染色 + 微发光。
如需改成按 **EVE 帝国**（阿玛尔/加达里/盖伦特/米玛塔尔，取自 SDE `raceID`）染色，
把 `src/shared/hullclass.ts` 里的 `ICON_TINT_MODE` 改成 `"empire"` 即可
（改后红蓝由外圈标识，两种信息都不丢）。

### 指挥脉冲：怎么"开启"（V0.6）

指挥舰的指挥脉冲模块在右栏「装备与火力」里就是**一个按钮**，标签形如
`指挥脉冲·Armor Energizing (2/2)`（弹药名取自 SDE，用于区分是哪一路脉冲）。
**点一下 = 开启，再点一下 = 关闭** —— 引擎按模块 `active` 门控，
关闭后该舰**不再向同舰队成员**提供这一路加成（战区测试第 18 组有断言）。

### 铁骑 / 无人机的行动（V0.6）

组的坐标不再"等同于母舰位置"，而是它自己的：
出仓点 = 母舰落点 → **自主飞向目标** → 抵达**最佳射程**后**按 `maxVelocity` 平速环绕**。

- 环绕半径：铁骑用 `orbitRange`、无人机用最佳射程；速度恒为 `maxVelocity`（方向取切向）。
- 射程 / 命中 / 锁定 / 立体炸弹的判定一律改用组的**自身坐标**（`phaseGroupMovement`）。
- 沙盘上用三角形（铁骑）/ 方块（无人机）画出组的实际位置，并连一条系留线到母舰，
  复盘时"已经出仓离开母舰"一眼可见。
- 实现上踩过两个坑（都已修，并被断言锁住）：赶路时必须**收在环绕半径上**
  （否则一步跨过去，铁骑会贴在目标身上转）；加了这个收束后还要留 **1 m 容差**

## 铁骑（战斗机）

一个发射管 = 一个纵队（D-27）。数据全部来自 PYFA，且**已核对口径**：

| 铁骑 | 攻击能力 | 远程导弹能力 |
|---|---|---|
| Templar I（轻，规模 6） | 1096.9 / 5 s = **219 DPS** | 2008.1 / 14 s = 143 DPS |
| Templar II | 1336.5 / 5 s | 2431.7 / 14 s |
| Cyclops I（重，规模 6） | 5146.9 / 5 s = **1029 DPS** | 41146.9 / **40 s** = 1028 DPS |
| Standup Templar I（建筑，规模 9） | 1521 / 5 s | 2781 / 40 s |

**口径验证**：`per-effect 齐射 = SDE 基础伤害 × 纵队规模 × 技能乘数`，
且各能力之和 == PYFA 的 `getVolley()`（Templar I：97.5×6×1.875=1096.875 ✓）。
一艘航母（2 轻 + 1 重）≈ **1467 DPS**，与实际相符。

实现要点：
- **每个纵队可带多个攻击能力**，按距离取"期望 DPS 最高"的一个
  （贴身选 5 s 的攻击、拉远选长周期导弹）——`core/combat.ts` 的 `fighterShotAt`。
- 铁骑**不是炮台**：伤害按**导弹公式**应用（爆炸半径/速度 + DRF/DRS）。
- HP 按组：血池 = 单架 HP × 纵队规模；输出按 D-25 线性折算。
- ★ 坑：`getVolleyParametersPerEffect()` 里**微型跃迁**这类零伤害能力也会出现，
  必须剔除，否则引擎会把它当成一门射程很远、伤害为零的"武器"。

## 脑插（技能植入体）

★ 用户的规则：**配置里有脑插才算，没有就不算**。`BattleConfig.implants` 不填 = 全程不吃加成。

★ **实现坑**：脑插必须挂在 **`Fit`** 上（`fit.implants`），**挂 `Character` 完全无效** ——
我试过 5 种 Character 侧接法（append / 回指 / 显式 `calculateModifiedAttributes` /
`char.fits` / 顺序调换）全部"无变化"，换到 `fit.implants` 立刻生效。

实测：

| 配置 | 护盾（启示级海军型） |
|---|---|
| 无脑插 | 11000 |
| 只装单件（Nirvana Alpha） | 11126.5（+1.15%） |
| 高级极乐全套 6 件 | **16899.7（+53.63%）** |

套装机制天然体现（单件几乎没用、成套才爆发）。

## 指挥脉冲（Command Burst）

实战形态是"满级技能 + 指挥舰船体加成 + 指挥脉冲脑插"，PYFA 里对应
`applyCommandLinkToFit(fit, CommandLink(linkType, strength, mindlink))`：

- `strength` 0..5 → 5 = 指挥舰/T3 + 满级技能
- `mindlink` = 是否带指挥脉冲脑插
- 三者被折算进 `getLinkMultiplier(strength, mindlink)`（实测 5 + 脑插 → ×2.9296875）

实测（启示级海军型，装甲 EM 共振 0.5 为基准）：

| link | 强度 5 | 强度 5 + 脑插 |
|---|---|---|
| `armor_energizing` | 0.40625（+18.75% 抗性） | **0.3828125（+23.4%）** |
| `armor_reinforcement` | 装甲 HP 17144.5 | **17821.3** |
| `shield_harmonizing` | 盾 EM 1.0 → 0.8125 | → 0.765625 |
| `info_sensor` | 锁定距离 114000 → 162093 | → 174117 |
| `skirmish_evasive` | 信号 370 → 317.97 | → 304.96 |

**多重叠加生效**（同时挂 装甲激能 + 装甲强化）。按势力给（`BattleConfig.envBySide`）。

★ **两个坑**：
1. `applyCommandLinkToFit` **只在"算过一次之后再重算"才生效** —— 只 apply 不算 = 无变化。
2. 拼错 `linkType` 在 PYFA 里是**静默无效**（不报错）。我们**先校验** `COMMAND_LINK_DEFS`，
   非法类型记入 `unhandled` —— 宁可报错也不让玩家以为脉冲挂上了其实没挂。

## 缓存键（关键正确性）

`envKey` = **脑插 + 指挥脉冲**的指纹；`fitFingerprint` 现在也包含**铁骑与无人机**。

★ 这不是"优化"，而是**正确性**：同一套配装"有脑插"与"没脑插"算出的属性完全不同
（+53.6% 护盾），不进键就会两套结果**互相串用**。测试里专门断言了这一点。

## 交火目标层级（铁骑 / 无人机）

铁骑与无人机都是**实体**：有自己的血量池、信号半径、速度，会被导弹/炮火打到。
它们在舰队交火列表里**独立显示**（点击一行即把该组设为主目标）。

目标选择的优先级（用户规则）：

| 交火方式 | 行为 |
|---|---|
| **集中火力 / 自动攻击 / 自由开火** | **只打单位**（舰船/建筑）。铁骑必须被显式选中才打 |
| **集火舰载机**（新增） | 优先打**射程内**的敌方铁骑纵队；射程内没有敌铁骑，才回退到普通优先级 |
| 兜底 | 场上**没有可打的单位**时，才转向敌方铁骑（"母舰被击毁后随后才攻击舰载机"） |
| 无人机 | **永不主动选择**（只被立体炸弹这类范围伤害波及） |

实现要点（`src/core/targeting.ts`）：

- `Unit.targetId` 仍指**母舰**（位置/射程/锁定沿用原逻辑），另用
  `targetKind` + `targetGroupId` 指明是哪一组 —— 改动面最小。
- 打组时用一个**轻量替身**作为目标：位置沿用母舰，**信号半径与速度换成组自己的**，
  于是既有的炮台追踪/导弹应用率公式**原样复用**（另写一套正是上一版出错的地方）。
- 锁定时长按**组自己的信号半径**算 —— 铁骑又小又快，锁它本来就比锁母舰慢。
- 伤害落到**组的血池**，按 D-25 线性折算输出比例；打光即整组消失并记入战报。
- 无人机组同样支持被打击（数据结构已就位），只是选择器不会主动选它们。

实测（战区测试 §15）：普通模式下打 600 tick，铁骑血量**分毫未动**（25238/25238）；
切到「集火舰载机」后同一局面下铁骑被打到 18882/25238（输出降到 74.8%）。

## 指挥脉冲的作用域（按舰队 + 按位置）

场景里用 `commandBurstSources` 声明每一路脉冲：

```ts
{ unitId, linkType: "armor_energizing", strength: 5, mindlink: true, rangeM: 40_000, moduleIndex: 0 }
```

受益判定（`src/core/commandLink.ts`）：

1. **同势力 + 同舰队** —— 跨舰队不受益（用户规则的核心）；
2. 源可用（存活在场）；
3. 若绑定了 `moduleIndex`：该模块必须处于 **active**（开/关模块就等于开关脉冲）；
4. 在 `rangeM` 射程内；
5. 同种 linkType 多源时 **取加成最高者**（按 PYFA 的 `getLinkMultiplier` 比较），
   并**按它自己的射程**决定覆盖范围 —— 于是"交集内取强、交集外各取自己"自然成立。

★ 因为每个单位位置不同，生效集合就不同 → 引擎的做法是：

- 启动时枚举每个舰队的**全部子集**（去重后通常很少），逐一预热成 `envKey`；
  一个真实局面必然是其中之一，所以预热是**完备**的；
- `envKey` 现在是属性表缓存键的一部分（`单位|状态位图|环境键`）；
- 每 tick 在 `commands` 阶段按位置求解一遍，**只有集合变了**才切换属性表，
  且切换时**保留运行期状态**（开火开关/冷却/组血量）—— 不会"一进范围就被重置"。

倍率公式 `(1+0.05·s) × 1.5 × 1.25 × (mindlink?1.25:1)` 与 PYFA 的 `getLinkMultiplier`
**12 个组合逐值比对一致**，且测试每次都会拿 oracle 的 `linkTable` 复核（防 PYFA 升级后错位）。

实测（场景 `command-burst`，两艘指挥舰同属蓝方舰队 0：A 强 5+脑插 40km、B 弱 2 10km）：

| 单位 | 情况 | 装甲 EM 共振 |
|---|---|---|
| 基线 | 两路都够不着 | 0.5000 |
| 只在 A 内 | 拿到 A | 0.3828 |
| **A ∩ B** | **取最强 → 等于只被 A 覆盖** | **0.3828** |
| 跨舰队 | 在 A 射程内但属另一舰队 | **0.5000（不受益）** |

## 立体炸弹（smartbomb）

数据取自 SDE 实测：`empFieldRange`（作用半径）+ `em/thermal/kinetic/explosiveDamage`
（EMP 型只给 `emDamage=300`），循环 `duration=10s`。例：Large EMP Smartbomb II → 6km / 300 EM。

引擎里是**独立阶段** `smartbombs`（§6.3 阶段表的第三处显式补充），
必须排在 `weaponFire` **之后** —— 该阶段开头会清空 `pendingHits`。

★ 忠实复现 EVE 行为：

- **不需要锁定、不需要目标**（这是它与武器的根本区别）；
- **六亲不认**：友军的舰船照炸；
- **但不炸自己**（发起引爆的舰不吃自己的炸弹）；
- **铁骑/无人机同样被打**（它们是实体）；
- 挂在舰上的**组会跟着母舰一起被判定是否在范围内**。

实测（场景 `smartbomb`，两枚炸弹相距 2km，跑 12 tick = 2 次引爆）：
红方受伤 **1200**（= 2 枚 × 2 次 × 300）、友军 **600**、铁骑血池 25238 → **24038**。

★ 实现坑：PYFA 的 `module.canDealDamage()` 对立体炸弹**也为真**，
若不排除就会被当成"炮台"，读到一份全 0 的伤害。已在 oracle 侧加 `_NON_WEAPON_KINDS` 白名单排除。

## 已知缺口

1. **指挥脉冲的"从配装反推"还没做**：目前由场景用 `commandBurstSources` **显式声明**
   每一路脉冲（含 strength / mindlink / 射程）。要改成"扫指挥舰的指挥脉冲模块 +
   弹药名，自动推出 linkType 与强度"，还差一步映射（PYFA 的 `COMMAND_LINK_DEFS`
   里已有 linkType ↔ 名称表，可用；强度则取决于船体与技能，需要玩家或场景指定）。
2. **组的抗性未细分**：铁骑/无人机的血池目前按**纯血量**扣（不细分盾/甲/构，也不做抗性下渗）——
   这是显式简化。`hpEach` 分层数据已在契约里，需要时可以细化。
3. ~~**组的独立轨道运动未建模**~~ → **V0.6 已实现**：组有自己的 `pos`/`vel`，
   出仓后自主飞向目标、抵达最佳射程后**按 `maxVelocity` 平速环绕**；
   射程/命中/锁定/立体炸弹判定一律改用组自身坐标（`phaseGroupMovement`）。
   仍未做的是**逐架点名**（组内个体不单独结算，仍按比例折算）。

## 架构铁律（单向依赖）

```
UI ──读状态/发命令──▶ 引擎 ──读属性表──▶ 属性缓存 ──查询──▶ StatOracle ──读──▶ 数据层
```

- UI **不得**直接改引擎对象；所有变更走"命令"。
- 引擎 **不得**直接调用 PYFA；所有属性查询走"属性缓存"。
- StatOracle **只回答叠加结果与原始武器参数**，**不回答"应用后 DPS"**（由引擎按目标实时状态计算）。

## 已确认的关键约束（详见第 4 章冻结稿）

1. `module.state` 必须显式设为 `active`，否则 `getVolley()` 恒为 0。
2. DPS 一律按 `volley / (cycle/1000)` 计算（PYFA 的 `getDps()` 内部有未初始化引用）。
3. 精简核 = `eos` + 依赖；`gui/` 与 `service/` 必须排除（会拉入整套 GUI）。
4. 子进程需定期重启（建议每 2000~5000 次请求），以规避 PYFA 内部缓存滞留。
5. **合规**：若随包分发提取出的 PYFA 代码，需履行 GPLv3 义务；推荐"用户机器现场提取"路线。
